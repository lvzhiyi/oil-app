# 编码核心原则
- **设计模式**：严格遵循行业标准的六大设计原则（SOLID）。保持代码的高内聚、低耦合、单一职责。
- **性能与维护**：优先考虑代码的执行性能与长期可维护性。代码应清晰、简洁、健壮。
- **最小化变更**：仅对实现目标绝对必要的代码进行修改。不要为了风格偏好而重写现有代码，除非涉及重大重构。

# 注释规范 (STRICT)
- **拒绝废话**：严禁包含“优化：结构更清晰”、“提取公共方法”或“修改了逻辑”等描述性/元数据注释。
- **关键注释**：仅在复杂的算法、非直观的逻辑或关键业务规则处添加解释性注释（解释 "Why" 而不是 "What"）。
- **无残留**：代码中不得包含任何被注释掉的旧代码或无关的调试信息。
