## 引言
本规范文档旨在为油品业务管理应用（Oil Business App）的开发提供高级指导原则。文档基于项目中的 `openspec/project.md` 文件详细约定，系统性地阐述了代码风格、架构模式、性能优化、安全考虑以及AI协作等关键方面的最佳实践。通过遵循这些规范，开发团队可以确保代码的一致性、可维护性和高性能，从而构建一个稳定可靠的跨平台移动应用。

## 代码风格规范
本节详细说明了项目中必须遵守的代码风格和命名约定，以确保代码库的统一性和可读性。

### 命名约定
项目严格遵循Dart和Flutter的官方编码规范，并在此基础上定义了具体的命名规则：
- **类名 (Class Names)**: 使用帕斯卡命名法（PascalCase），即每个单词的首字母大写，例如 `LoginController`、`UserProfileState`。
- **变量、方法、参数 (Variables, Methods, Parameters)**: 使用驼峰命名法（camelCase），即第一个单词小写，后续单词首字母大写，例如 `loginLoading`、`submitForm()`、`phoneNumber`。
- **常量 (Constants)**: 使用全大写蛇形命名法（UPPER_SNAKE_CASE），即所有字母大写，单词间用下划线分隔，例如 `MAX_LOGIN_ATTEMPTS`、`API_BASE_URL`。
- **文件名和包名 (File and Package Names)**: 使用小写蛇形命名法（lowercase_with_underscores），即所有字母小写，单词间用下划线分隔，例如 `user_profile.dart`、`network_utils`。

### 使用final和const
为了提升代码的可预测性和性能，项目鼓励最大限度地使用不可变性：
- **final变量**: 尽可能将变量声明为 `final`，表示其值在初始化后不可更改。这有助于防止意外的修改，并使代码意图更清晰。
- **const构造函数**: 在创建Widget、集合或任何不可变对象时，尽可能使用 `const` 构造函数。这允许Dart编译器在编译时创建对象，从而避免在运行时重复创建，显著提升性能。

### 文档注释
清晰的文档注释是代码可维护性的关键：
- **文档注释 (///)**: 使用三个斜杠 `///` 来添加文档注释。这些注释应位于类、方法、函数和公共变量的上方，用于描述其功能、参数、返回值和使用示例。
- **行内注释 (//)**: 使用双斜杠 `//` 来添加行内注释，用于解释复杂的逻辑或代码背后的决策。

## 架构模式
本节深入讲解了项目的整体架构设计，特别是其“功能优先”（Feature-first）的目录结构和页面标准。

### Feature-first 目录结构
项目采用“功能优先”的组织结构，将代码按功能模块进行划分，而非按技术层次。这种结构提高了代码的内聚性，使得查找和维护特定功能的代码变得非常直观。
```
lib/
├── pages/              # 按功能模块组织
│   └── login/          # 登录功能模块
│       ├── page.dart
│       ├── controller.dart
│       ├── state.dart
│       ├── view.dart
│       └── widgets/
├── widgets/            # 全局可复用组件
├── global/             # 全局状态和服务
├── net/                # 网络层
├── router/             # 路由配置
├── config/             # 配置文件
├── resources/          # 资源文件（颜色、尺寸、主题）
└── utils/              # 工具类
```

### 页面标准
每个功能模块都遵循一套标准化的文件结构，包含四个核心文件：
1.  **page.dart**: 路由入口文件。它继承自 `BasePage`，负责注册该页面的BLoC/Cubit控制器，并通过 `BlocProvider` 和 `BlocBuilder` 将状态与视图连接起来。
2.  **controller.dart**: 业务逻辑控制器。它继承自 `Cubit` 或 `Bloc`，负责处理业务逻辑、调用API服务，并管理页面状态的变更。
3.  **state.dart**: 状态定义文件。它是一个不可变的数据类，必须包含 `copyWith` 方法，以便在不修改原对象的情况下创建新的状态实例。
4.  **view.dart**: 视图实现文件。它是一个 `StatefulWidget` 或 `StatelessWidget`，负责监听状态变化（使用 `BlocListener`）并调用 `widgets/` 目录下的具体UI组件来组装页面。

## 性能优化实践
本节强调了项目中为确保应用流畅性而采用的关键性能优化技术。

### 使用const构造函数
如前所述，广泛使用 `const` 构造函数是性能优化的基础。它减少了运行时对象的创建开销，尤其是在构建树中重复出现的Widget。

**Section sources**
- [project.md](file://openspec/project.md#L752-L753)

### ListView.builder进行懒加载
对于包含大量数据的列表，必须使用 `ListView.builder` 而不是 `ListView`。`ListView.builder` 采用懒加载机制，只会在需要时创建和渲染可见的列表项，从而极大地节省内存和提升滚动性能。

```dart
ListView.builder(
  itemCount: items.length,
  itemBuilder: (context, index) => MyListItem(items[index]),
)
```

### gaplessPlayback避免图片闪烁
在使用 `Image.asset` 或 `Image.network` 时，应设置 `gaplessPlayback: true`。这个属性可以确保在图片加载完成或更新时，不会出现短暂的空白或闪烁，提供更流畅的视觉体验。

```dart
Image.asset(
  AssetsIcon.IC_SEARCH,
  gaplessPlayback: true,
)
```

## 安全考虑
本节重申了项目中关于数据安全和API调用的关键安全实践。

### 敏感信息的本地存储
敏感信息（如用户凭证、会话令牌）的本地存储必须遵循安全原则：
- **Hive/SharedPreferences**: 项目使用 `Hive` 和 `SharedPreferences` 进行本地存储。`Hive` 用于存储结构化数据，而 `SharedPreferences` 用于存储简单的键值对。
- **加密**: 虽然 `SharedPreferences` 本身不提供加密，但应避免直接存储明文密码。对于高度敏感的信息，应考虑使用额外的加密层或专用的安全存储库。

### API调用的安全性
网络请求的安全性至关重要：
- **拦截器链路**: 项目通过一系列拦截器来增强API调用的安全性。`HttpHeaderInterceptor` 负责添加认证头（如Token），`BaseInterceptor` 处理Token过期和自动刷新，`HttpRespInterceptor` 统一处理错误和状态码。
- **HTTPS**: 所有API调用必须通过HTTPS协议进行，以加密传输数据，防止中间人攻击。

## AI协作规范
本节引用了 `GEMINI.md` 和 `CLAUDE.md` 中的AI协作规范，说明了如何利用AI工具进行高效的代码生成和审查。

### 利用AI进行代码生成
AI工具可以作为强大的辅助，用于：
- **生成样板代码**: 快速生成符合项目规范的页面、控制器、状态类等文件的初始结构。
- **实现算法**: 根据描述生成复杂的业务逻辑或数据处理算法。
- **生成测试用例**: 为现有代码生成单元测试或集成测试的框架。

### 利用AI进行代码审查
AI工具在代码审查中扮演着重要角色：
- **规范检查**: 自动检查代码是否符合命名约定、代码风格和项目规范。
- **潜在错误识别**: 识别潜在的空指针异常、内存泄漏或性能瓶颈。
- **文档生成**: 根据代码自动生成或完善文档注释。
