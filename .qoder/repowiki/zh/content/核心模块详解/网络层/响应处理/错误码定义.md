## HttpCode类静态常量列表

根据项目代码分析，`HttpCode`类定义了以下静态常量，用于表示后端业务逻辑返回的自定义编码：

- **success**：值为 `1`，表示请求成功
- **logout**：值为 `401`，表示登录失效
- **tokenExpired**：值为 `401`，表示token过期

这些常量在`lib/net/code.dart`文件中定义，专门用于区分业务层面的成功与失败状态。

## 业务错误码与HTTP状态码的区别

业务错误码与HTTP状态码存在本质区别：

- **HTTP状态码**：属于网络协议层面的标准响应码（如200、404、500），由服务器或网络层返回，表示请求的网络传输状态。
- **业务错误码**：是后端服务在业务逻辑处理过程中自定义的编码，用于表达具体业务场景下的成功或失败情况。例如，即使HTTP状态码为200（请求成功），业务错误码也可能为非1值，表示业务处理失败。

本项目中的`HttpCode`类定义的常量属于**业务错误码**，不依赖于HTTP状态码，而是通过响应体中的`code`字段传递，供前端根据业务逻辑进行相应处理。

## 实际开发中的条件判断应用

在实际开发中，开发者通过判断`res.code`的值来执行不同的逻辑分支。例如，在HTTP响应拦截器中：

```dart
if (res.code == HttpCode.success) {
  // 请求成功，继续处理数据
  return handler.next(...);
} else {
  // 根据错误码进行相应处理
  handleResponseError(response, handler);
}
```

当检测到`logout`或`tokenExpired`（均为401）时，系统会触发登出流程并跳转至登录页，提示用户重新登录。这种机制确保了用户在会话失效后能够及时重新认证，保障系统安全。

## 错误码到用户提示语的映射策略

项目通过多语言资源文件实现错误码与用户提示语的映射，支持国际化友好提示：

- 中文提示语定义于 `assets/translations/zh.json`
- 英文提示语定义于 `assets/translations/en.json`

虽然当前实现中未直接通过`switch-case`或`Map`映射错误码到提示语，但可通过统一的错误处理工具类，结合多语言资源，实现如下策略：

```dart
String getErrorMessage(int code) {
  switch (code) {
    case HttpCode.logout:
    case HttpCode.tokenExpired:
      return i18n.loginExpireTips; // 多语言支持
    default:
      return i18n.defaultError;
  }
}
```

建议未来将错误提示集中管理，提升可维护性与多语言支持能力。

## 命名规范建议

为保证代码可读性与一致性，建议在扩展`HttpCode`类时遵循统一的命名规范：

- 使用**小驼峰命名法**（lowerCamelCase）
- 常量名应**语义清晰**，如`networkError`、`dataNotFound`等
- 避免使用HTTP状态码数字作为业务逻辑判断依据
- 添加必要的文档注释，说明每个常量的触发场景

例如：
```dart
/// 网络连接失败
static const networkError = 1000;

/// 数据未找到
static const dataNotFound = 1001;
```

这有助于团队成员快速理解业务含义，降低维护成本。
