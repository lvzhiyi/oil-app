## 网络层架构概述

本项目网络通信模块采用Dio作为HTTP客户端库，通过NetManager单例模式进行封装管理。网络层采用拦截器链模式实现日志记录、请求头注入、响应处理等功能的解耦。整体架构遵循分层设计原则，将网络请求的通用处理逻辑与业务逻辑分离，提高了代码的可维护性和可扩展性。

## 拦截器链设计与执行流程

网络层采用拦截器模式构建了三层拦截器链，按照特定顺序执行，确保请求和响应的正确处理。拦截器链的构建顺序在NetManager的init方法中定义，遵循"日志→头信息→响应处理"的原则。

```mermaid
flowchart TD
A[请求发起] --> B[HttpLogInterceptor]
B --> C[HttpHeaderInterceptor]
C --> D[HttpRespInterceptor]
D --> E[发送HTTP请求]
E --> F[接收响应]
F --> G[HttpRespInterceptor]
G --> H[HttpHeaderInterceptor]
H --> I[HttpLogInterceptor]
I --> J[返回结果]
```

## HTTP请求统一处理规范

网络层实现了HTTP请求的统一处理规范，包括请求头自动注入、错误码统一处理、响应数据解析和异常转换等核心功能。

### 请求头自动注入

HttpHeaderInterceptor负责为每个请求自动注入必要的头信息，包括内容类型、认证令牌和设备信息。登录接口等特定请求会跳过认证令牌的注入。

```mermaid
sequenceDiagram
participant Client
participant HeaderInterceptor
participant Request
Client->>HeaderInterceptor : 发起请求
HeaderInterceptor->>HeaderInterceptor : 判断是否为登录接口
alt 非登录接口
HeaderInterceptor->>HeaderInterceptor : 注入Authorization头
end
HeaderInterceptor->>HeaderInterceptor : 设置Content-Type
HeaderInterceptor->>HeaderInterceptor : 注入设备信息头
HeaderInterceptor->>Request : 继续请求流程
```

## 认证令牌刷新与错误处理

网络层实现了完善的认证令牌刷新机制，能够自动处理令牌过期的情况，提升用户体验。

### 令牌刷新流程

当服务器返回401或403状态码时，HttpRespInterceptor会自动尝试刷新令牌。系统通过Completer模式确保同一时间只有一个刷新请求在执行，避免并发刷新问题。

```mermaid
flowchart TD
A[收到401/403响应] --> B{是否正在刷新?}
B --> |是| C[等待刷新完成]
B --> |否| D[开始刷新令牌]
D --> E[调用refreshToken接口]
E --> F{刷新成功?}
F --> |是| G[更新认证信息]
F --> |否| H[退出登录]
G --> I[重新发送原始请求]
H --> J[跳转登录页]
```

## 自定义拦截器开发指南

开发者可以基于BaseInterceptor基类创建自定义拦截器，以满足特定的业务需求。

### 创建自定义拦截器

要创建自定义拦截器，需要继承BaseInterceptor类，并重写onRequest、onResponse或onError方法。每个拦截器都需要提供唯一的标签（tag）用于日志记录和调试。

```mermaid
classDiagram
class CustomInterceptor {
+CustomInterceptor()
+onRequest()
+onResponse()
+onError()
}
BaseInterceptor <|-- CustomInterceptor
```

### 处理复杂场景

#### 认证令牌刷新

对于需要处理认证令牌刷新的场景，可以参考HttpRespInterceptor的实现。关键是要使用静态Completer来管理并发刷新请求，确保线程安全。

#### 请求重试机制

系统可以通过在onError方法中实现重试逻辑来处理临时性网络错误。建议设置最大重试次数和重试间隔，避免无限重试。

```mermaid
flowchart TD
A[请求失败] --> B{是否可重试?}
B --> |是| C[等待重试间隔]
C --> D[重试请求]
D --> E{重试次数达到上限?}
E --> |否| B
E --> |是| F[返回错误]
B --> |否| F
```
