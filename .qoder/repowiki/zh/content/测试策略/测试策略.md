## 测试金字塔结构

本项目采用分层的测试金字塔策略，确保代码质量和稳定性。测试金字塔由三层构成：底层是大量的单元测试，中间层是组件测试，顶层是少量的集成测试。这种结构确保了测试的高效性和可靠性。

```mermaid
graph TD
A[集成测试] --> |少量| B[组件测试]
B --> |中等数量| C[单元测试]
C --> |大量| D[utils和model]
```

## 测试类型与最佳实践

### 单元测试

单元测试是测试金字塔的基础，主要针对`utils`和`model`目录下的独立函数和类。这些测试确保核心逻辑的正确性，例如表单验证、数据转换等。

```mermaid
flowchart TD
Start[开始] --> ValidateInput["验证输入参数"]
ValidateInput --> InputValid{"输入有效?"}
InputValid --> |否| ReturnError["返回错误响应"]
InputValid --> |是| ProcessData["处理数据"]
ProcessData --> ReturnResult["返回结果"]
ReturnError --> End[结束]
ReturnResult --> End
```

### 组件测试

组件测试针对独立的UI组件，如登录页面的表单字段、按钮等。这些测试确保组件在不同状态下的行为符合预期。

```mermaid
sequenceDiagram
participant 用户 as 用户
participant 组件 as 组件
participant 测试 as 测试框架
用户->>组件 : 输入手机号
组件->>测试 : 验证输入
测试->>组件 : 返回验证结果
组件->>用户 : 显示验证状态
```

### 集成测试

集成测试覆盖完整的页面流程，如登录流程、密码重置流程等。这些测试确保各个组件协同工作，流程顺畅。

```mermaid
sequenceDiagram
participant 用户 as 用户
participant 页面 as 页面
participant 服务 as 服务
用户->>页面 : 提交登录表单
页面->>服务 : 调用登录API
服务->>页面 : 返回登录结果
页面->>用户 : 显示登录成功或失败
```

## 测试框架与工具

本项目使用Flutter Test框架进行测试，结合Mockito进行依赖模拟，以及bloc_test来测试BLoC的状态转换。这些工具确保测试的独立性和可靠性。

```mermaid
classDiagram

+expect()
}

+when()
+verify()
}

+emit()
}
```
