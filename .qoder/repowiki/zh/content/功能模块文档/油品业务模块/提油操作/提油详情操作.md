## 提油详情页面流程概述

提油详情页面（oil_pickup_detail）是油品提油业务的核心操作界面，负责处理用户从选择库存到提交提油申请的完整流程。该页面通过路由参数接收库存信息，初始化控制器，并提供车辆信息录入、提油量输入、加油站选择等核心功能。用户完成信息填写后，可提交提油申请，调用后端API生成提油凭证，并导航至成功页面。整个流程采用Bloc模式进行状态管理，确保UI与业务逻辑分离，提升代码可维护性。

## 页面初始化与路由参数处理

提油详情页面的入口通过路由系统配置，当用户从库存列表点击进入时，系统会携带`InventoryModel`对象作为路由参数。`routes.dart`文件中定义了`oilPickupDetailPage`路由，其`builder`方法接收`state.extra`中的`InventoryModel`对象，并将其传递给`OilPickupDetailPage`构造函数。

```dart
case AppPage.oilPickupDetailPage:
  return (context, state) =>
      OilPickupDetailPage(inventory: state.extra as InventoryModel);
```

`OilPickupDetailPage`是一个`BasePage`，它接收`InventoryModel`作为必需参数。在`_OilPickupDetailPage`的`body`方法中，使用`BlocProvider`创建`OilPickupDetailCtrl`实例，并将`InventoryModel`作为构造参数传入。控制器的构造函数接收`InventoryModel`并初始化`OilPickupDetailState`，将库存信息存储在状态中，供后续业务逻辑使用。

```dart
class OilPickupDetailCtrl extends Cubit<OilPickupDetailState> {
  OilPickupDetailCtrl(InventoryModel inventory)
      : super(OilPickupDetailState(inventory: inventory)) {
    initState();
  }
  // ...
}
```

## 车辆信息表单设计与验证

车辆信息表单（`vehicle_info_form`）是用户输入车辆及司机信息的核心组件。该表单采用`StatelessWidget`实现，通过`TextEditingController`管理各个输入字段的状态。表单包含以下字段：

- **车牌号码**：必填，使用`_buildTextField`构建，带有红色星号标识。
- **司机姓名**：必填。
- **身份证号**：必填。
- **联系电话**：必填，使用`TextInputType.phone`键盘，并通过正则表达式`^1[1-9]\d{9}$`验证手机号格式。
- **驾驶证编码**：选填。
- **行驶证编号**：选填。
- **车型**：选填。
- **单双仓**：选填。
- **是否带泵**：选填。
- **核定载重(吨)**：选填，使用数字键盘。
- **一仓(吨)**：选填，使用数字键盘。
- **二仓(吨)**：选填，使用数字键盘。

表单采用`Column`和`Row`布局，将相关字段分组显示，提升可读性。`_buildTextField`方法封装了输入框的通用样式，包括标签、提示文本、验证器和输入类型。必填字段的标签前会添加红色星号。输入框的样式包括圆角背景、阴影和不同状态下的边框颜色（正常、聚焦、错误）。

## 车辆信息解析与JSON转换

系统提供了两种方式录入车辆信息：手动填写和智能解析。智能解析功能由`SmartParseCard`组件提供，用户可将包含车辆信息的文本（如调度单）粘贴到文本框中，系统会自动解析并填充表单。

### 智能解析流程

`SmartParseCard`包含一个`TextField`和两个操作按钮：“复制模板”和“点击粘贴”。当用户粘贴文本或手动输入时，`onChanged`回调会触发`onParse`函数，该函数由`OilPickupDetailCtrl`的`onVehicleInfoPasted`方法实现。此方法会重置控制器状态，清除之前的解析结果。

```dart
void onVehicleInfoPasted(String text) {
  emit(state.copyWith(
    vehicleInfo: text.trim(),
    vehicleModel: null,
    missingFields: const [],
    parseSuccess: false,
    errorMessage: null,
  ));
}
```

### VehicleInfoParser工具类

`vehicle_info_parser.dart`是核心解析工具，它使用正则表达式和关键词匹配来提取信息。

1.  **预处理**：将所有已知关键词（如“车牌号”、“司机姓名”）前强制添加换行符，解决“姓名:张三电话:123”这类无分隔符的问题。
2.  **特征提取**：
    *   使用正则表达式提取强特征字段，如手机号`1[3-9]\d{9}`、身份证`\d{17}[\dXx]`、车牌号`[京津沪...][A-Z][A-Z0-9]{5,6}`。
    *   使用关键词匹配提取其他字段，如“驾驶员姓名”、“核定载重”。
3.  **值清理**：移除提取值中的单位（如“吨”、“公斤”）和首尾标点符号。
4.  **组装模型**：将提取到的字段组装成`VehicleModel`对象。

### JSON转换

`VehicleInfoParser`提供了`toJson`静态方法，将`VehicleModel`对象序列化为JSON字符串。在提交提油申请时，系统会根据用户输入情况构建`vehicleInfo`字段：

- 如果用户粘贴了文本，`vehicleInfo`格式为`原始文本|||JSON字符串`。
- 如果用户手动填写，`vehicleInfo`格式为`|||JSON字符串`（原始文本为空）。

这种设计既保留了原始信息，又提供了结构化数据。

## 提油申请提交流程

提交提油申请是整个流程的最终步骤，由`generateCertificate`方法驱动。

### 提交前验证

1.  **提油量验证**：调用`_validateOilAmount`方法，检查提油量是否为空、是否为有效数字、是否大于0，以及是否超过库存可用量。
2.  **车辆信息验证**：检查`vehicleInfo`字段是否为空。
3.  **加油站选择**：检查`selectedStation`是否已选择。

### 构建WithdrawRequest

验证通过后，系统构建`WithdrawRequest`请求体：
- `withdrawTon`：提油量（`double`类型）。
- `stationId`：所选加油站的ID。
- `vehicleInfo`：按上述规则构建的字符串。

### 调用API

通过`oilPickupService.submitWithdraw`方法调用`POST /inventories/{orderId}/withdraw`接口。`orderId`来自`state.inventory!.inventoryId!`。

```dart
final response = await oilPickupService.submitWithdraw(
  state.inventory!.inventoryId!,
  request,
);
```

### 状态同步与导航

- **加载状态**：在API调用前，设置`isLoading: true`，禁用提交按钮并显示加载指示器。
- **成功处理**：API调用成功后，设置`isLoading: false`，并通过`BaseRouter.push`导航至`oilPickupSuccessPage`，同时传递提油响应、库存信息、加油站信息、提油量、车辆模型和调度信息等数据。
- **错误处理**：捕获异常，设置`isLoading: false`，并显示Toast提示“提交失败，请重试”。

## 状态管理与用户体验

系统采用`flutter_bloc`库进行状态管理，`OilPickupDetailCtrl`作为`Cubit`管理`OilPickupDetailState`。所有UI变更都通过`emit`新状态来驱动，实现了单向数据流。

### 表单状态更新

- **提油量输入**：`TextField`的`onChanged`回调调用`updateOilAmount`，该方法会实时验证输入并更新状态中的`oilAmount`和`errorMessage`。
- **车辆信息更新**：`onVehicleInfoPasted`方法更新`vehicleInfo`字段，并触发解析。

### 加载指示器控制

`CommonButton`组件的`isLoading`属性绑定到`state.isLoading`。当`generateCertificate`方法开始执行时，`isLoading`被设为`true`，按钮进入加载状态；无论成功或失败，最终都会被设为`false`，恢复按钮。

### 错误反馈处理

错误信息通过`state.errorMessage`统一管理。该信息会显示在提油量输入框下方，颜色根据是否存在错误而变化（红色或灰色）。此外，表单字段自身的`validator`会在用户交互时提供即时反馈。

## 用户体验优化建议

1.  **增强智能解析**：当前解析基于关键词和正则，对于格式不规范的文本可能失败。可引入更高级的NLP模型或机器学习算法，提高解析准确率。
2.  **表单自动填充**：对于经常使用的车辆信息，可增加“常用车辆”功能，允许用户保存模板，一键填充。
3.  **提油量快捷输入**：增加“全部提走”按钮，自动填充为可用库存的最大值。
4.  **更详细的错误提示**：在提交失败时，应解析后端返回的`WithdrawResponse.message`，向用户展示具体的失败原因（如“库存不足”、“加油站已关闭”），而非笼统的“提交失败”。
5.  **离线支持**：在网络不稳定时，可将提油申请暂存于本地，待网络恢复后自动提交，提升用户体验。
6.  **输入引导**：在`SmartParseCard`中，除了“复制模板”，可增加一个“示例”按钮，展示不同格式的正确输入样例。
