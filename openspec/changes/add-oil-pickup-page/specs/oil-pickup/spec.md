# Oil Pickup Capability

## ADDED Requirements

### Requirement: 提油页面导航入口
系统 SHALL 在主导航栏的第二个 Tab 位置提供提油页面入口。

#### Scenario: 用户访问提油页面
- **WHEN** 用户点击主导航栏第二个 Tab
- **THEN** 系统应显示提油页面
- **AND** Tab 图标和文字应正确显示

### Requirement: 加油站选择功能
系统 SHALL 允许用户选择加油站作为提油地点。

#### Scenario: 首次选择加油站
- **WHEN** 用户首次进入提油页面且未选择加油站
- **THEN** 系统应显示"选择加油站"按钮
- **AND** 点击按钮应跳转到加油站列表页面

#### Scenario: 已选择加油站
- **WHEN** 用户已选择加油站
- **THEN** 提油页面应显示当前选中的加油站信息
- **AND** 加油站信息旁边应显示切换按钮
- **AND** 点击切换按钮应跳转到加油站列表页面

#### Scenario: 从列表选择加油站
- **WHEN** 用户在加油站列表页面点击某个加油站
- **THEN** 系统应选中该加油站
- **AND** 返回提油页面并显示选中的加油站信息

### Requirement: 加油站列表展示
系统 SHALL 提供加油站列表页面展示所有可用的加油站。

#### Scenario: 查看加油站列表
- **WHEN** 用户进入加油站列表页面
- **THEN** 系统应显示所有加油站的列表
- **AND** 每个列表项应显示加油站名称和地址
- **AND** 列表应支持滚动查看

#### Scenario: 空列表状态
- **WHEN** 没有可用的加油站数据
- **THEN** 系统应显示空状态提示
- **AND** 提示用户可以新增加油站

### Requirement: 加油站信息修改
系统 SHALL 允许用户修改已有加油站的信息。

#### Scenario: 进入编辑页面
- **WHEN** 用户在加油站列表项点击"修改"按钮
- **THEN** 系统应跳转到加油站编辑页面
- **AND** 页面应预填充当前加油站的信息

#### Scenario: 保存修改
- **WHEN** 用户修改加油站信息后点击保存按钮
- **AND** 表单验证通过
- **THEN** 系统应更新加油站信息
- **AND** 显示成功提示
- **AND** 返回加油站列表页面

#### Scenario: 取消修改
- **WHEN** 用户点击返回或取消按钮
- **THEN** 系统应丢弃未保存的修改
- **AND** 返回加油站列表页面

### Requirement: 新增加油站入口
系统 SHALL 提供新增加油站的入口按钮。

#### Scenario: 显示新增按钮
- **WHEN** 用户在加油站列表页面
- **THEN** 系统应在页面底部或固定位置显示"新增加油站"按钮

#### Scenario: 点击新增按钮(当前阶段)
- **WHEN** 用户点击"新增加油站"按钮
- **THEN** 系统暂不执行任何逻辑(预留后续开发)

### Requirement: 提油油量输入
系统 SHALL 提供输入提油油量的功能区域。

#### Scenario: 输入油量
- **WHEN** 用户在提油页面的输入框输入油量
- **THEN** 系统应接受数字输入
- **AND** 应显示提示文本"请输入本次提油量/吨"

#### Scenario: 油量验证
- **WHEN** 用户输入的油量不符合要求(如负数、非数字)
- **THEN** 系统应显示错误提示
- **AND** 不允许提交

### Requirement: 粘贴车辆信息展示
系统 SHALL 提供粘贴车辆信息的展示区域。

#### Scenario: 显示车辆信息区域
- **WHEN** 用户在提油页面
- **THEN** 系统应显示"粘贴车辆信息"的展示区域
- **AND** 区域应有明确的标题和边框样式

#### Scenario: 空车辆信息状态
- **WHEN** 用户尚未粘贴车辆信息
- **THEN** 系统应显示占位内容或提示

### Requirement: 车辆信息智能识别
系统 SHALL 自动识别和解析粘贴的车辆信息文本,并生成结构化的 JSON 数据。

#### Scenario: 粘贴标准格式车辆信息
- **WHEN** 用户粘贴包含完整字段的车辆信息文本
- **THEN** 系统应自动识别所有字段
- **AND** 生成包含所有字段的 JSON 字符串
- **AND** 在界面显示识别结果

#### Scenario: 粘贴乱序车辆信息
- **WHEN** 用户粘贴字段顺序不一致的车辆信息文本
- **THEN** 系统应通过关键词匹配正确识别各字段
- **AND** 生成正确的 JSON 数据结构

#### Scenario: 粘贴不完整车辆信息
- **WHEN** 用户粘贴缺少部分字段的车辆信息文本
- **THEN** 系统应识别出存在的字段
- **AND** 未识别的字段在 JSON 中设为 null 或空字符串
- **AND** 提示用户缺少的必填字段

#### Scenario: 识别多种格式变体
- **WHEN** 车辆信息包含不同的分隔符(冒号、等号、空格)
- **AND** 包含不同的换行方式
- **THEN** 系统应灵活解析并正确识别字段值
- **AND** 生成统一格式的 JSON 数据

#### Scenario: 查看识别后的 JSON
- **WHEN** 系统成功识别车辆信息
- **THEN** 用户应能够查看生成的 JSON 字符串
- **AND** JSON 应包含所有识别到的字段
- **AND** JSON 格式应正确可用于后续处理

### Requirement: 生成提油凭证
系统 SHALL 提供生成提油凭证的功能按钮。

#### Scenario: 显示生成凭证按钮
- **WHEN** 用户在提油页面
- **THEN** 系统应在页面底部显示"生成提油凭证"按钮

#### Scenario: 点击生成凭证(当前阶段)
- **WHEN** 用户点击"生成提油凭证"按钮
- **THEN** 系统应验证必填信息(加油站、油量)
- **AND** 验证通过后执行生成逻辑(具体逻辑待后续定义)

### Requirement: Mock 数据支持
系统 SHALL 使用 Mock 数据进行功能开发和测试。

#### Scenario: 加载 Mock 加油站数据
- **WHEN** 页面需要加油站数据
- **THEN** 系统应从 Mock 数据源加载预设的加油站列表
- **AND** Mock 数据应包含加油站名称、地址等必要字段

#### Scenario: Mock 数据修改
- **WHEN** 用户修改加油站信息
- **THEN** 系统应在内存中更新 Mock 数据
- **AND** 修改应在当前会话中保持

#### Scenario: Mock 数据选择
- **WHEN** 用户选择加油站
- **THEN** 系统应记录选中的加油站 ID
- **AND** 在提油页面正确显示选中的加油站信息

### Requirement: 响应式布局适配
系统 SHALL 确保提油相关页面在不同设备上正确显示。

#### Scenario: 手机端适配
- **WHEN** 用户在手机设备上访问提油页面
- **THEN** 所有组件应使用 AppSizes 工具进行尺寸适配
- **AND** 页面布局应适应手机屏幕宽度

#### Scenario: 平板端适配
- **WHEN** 用户在平板设备上访问提油页面
- **THEN** 页面应根据 AppSizes.isTablet 调整布局
- **AND** 字体和间距应正确缩放

#### Scenario: 深色模式适配
- **WHEN** 用户切换到深色模式
- **THEN** 所有颜色应使用 CustomAppColor.of(context) 动态获取
- **AND** 页面应正确显示深色主题样式
