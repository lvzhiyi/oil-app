系统 SHALL 提供提油订单详情页，允许用户查看已创建的提油订单的完整信息，并在待提油状态时支持取消申请。

#### Scenario: 从列表页跳转到详情页
- **WHEN** 用户在提油订单列表页点击某个订单列表项
- **THEN** 系统应跳转到提油订单详情页
- **AND** 应传递完整的订单数据（WithdrawOrderModel）到详情页
- **AND** 详情页应显示该订单的所有信息

#### Scenario: 显示提油订单信息
- **WHEN** 用户进入提油订单详情页
- **THEN** 页面应显示提油信息卡片，包含：
  - 提油单号（如果有）
  - 提油量（单位：吨）
  - 订单状态（待提油/已完成/已取消等）
  - 创建时间
  - 更新时间
- **AND** 信息应使用与提油成功页面相同的卡片样式和布局

#### Scenario: 显示加油站信息
- **WHEN** 用户进入提油订单详情页
- **THEN** 页面应显示加油站信息卡片，包含：
  - 加油站名称
  - 加油站地址
- **AND** 信息应使用与提油成功页面相同的卡片样式和布局

#### Scenario: 显示车辆及司机信息
- **WHEN** 用户进入提油订单详情页
- **AND** 订单包含车辆信息（vehicleInfo JSON 字符串）
- **THEN** 系统应解析 vehicleInfo JSON 字符串为 VehicleModel
- **AND** 页面应显示车辆及司机信息卡片，包含：
  - 驾驶员姓名（如果有）
  - 车号（如果有）
  - 驾驶员电话（如果有）
  - 身份证号（如果有）
  - 车型（如果有）
  - 核定载重（如果有）
- **AND** 信息应使用与提油成功页面相同的卡片样式和布局
- **AND** 如果某个字段为空，应隐藏该字段或显示默认值

#### Scenario: 页面布局结构
- **WHEN** 用户进入提油订单详情页
- **THEN** 页面应使用与提油成功页面相同的布局结构：
  - Scaffold + AppBar（显示“提油订单详情”标题，包含返回按钮）
  - Expanded + SingleChildScrollView（可滚动内容区域）
- **AND** 内容区域应包含：
  - 提油信息卡片
  - 加油站信息卡片
  - 车辆及司机信息卡片（如果有车辆信息）
- **AND** 卡片间距应与提油成功页面一致
- **AND** 当订单状态为待提油时，页面底部应通过 SafeArea 固定展示灰色背景、红色文字的“取消订单”按钮；订单状态非待提油时隐藏该按钮

#### Scenario: 返回按钮功能
- **WHEN** 用户在提油订单详情页点击 AppBar 的返回按钮
- **THEN** 系统应返回到提油订单列表页
- **AND** 列表页的状态应保持不变（保持之前的筛选和滚动位置）

#### Scenario: 数据为空处理
- **WHEN** 用户进入提油订单详情页
- **AND** 订单的某个字段为空（如提油单号、车辆信息等）
- **THEN** 系统应优雅处理空值：
  - 如果字段为空，应隐藏该字段或显示默认值
  - 如果 vehicleInfo 为空或解析失败，应隐藏车辆及司机信息卡片或显示提示信息
- **AND** 不应显示错误信息或导致页面崩溃

#### Scenario: 取消提油申请
- **WHEN** 订单状态为 `pending_pickup`
- **AND** 用户点击底部“取消订单”按钮
- **THEN** 系统应调用 POST `/inventories/withdraws/{withdrawId}/cancel` 接口，路径参数 `withdrawId` 取自订单数据，接口无需请求体
- **AND** 调用过程中按钮进入加载或禁用态以防重复提交
- **AND** 接口返回成功后刷新当前订单状态（按接口返回状态展示，待提油按钮隐藏），并提示取消成功
- **AND** 接口失败时提示错误信息且保持原状态
