## MODIFIED Requirements

### Requirement: 提油订单详情页展示
系统必须(SHALL)提供提油订单详情页,展示订单的完整信息,包括订单状态、提油量、加油站信息以及车辆和司机信息。

**实现变更**: 将单一大文件(816行)重构为模块化组件结构,提升代码可维护性。功能保持不变。

#### Scenario: 查看待提油订单详情
- **WHEN** 用户从订单列表进入待提油订单详情页
- **THEN** 系统显示运单卡片,包含:
  - 紫色渐变顶栏
  - 状态图标和"待提油"文字
  - 订单号
  - 核定提油量(吨)
  - 提油油库名称
  - 加油站名称
  - 车辆及司机信息(如果有)
  - 底部显示"取消订单"和"保存凭证"按钮

#### Scenario: 查看已完成订单详情
- **WHEN** 用户从订单列表进入已完成订单详情页
- **THEN** 系统显示运单卡片,包含:
  - 绿色渐变顶栏
  - 状态图标和"已完成"文字
  - 订单号
  - 实际提油量(吨,绿色高亮)
  - 提油油库名称
  - 加油站名称
  - 车辆及司机信息(如果有)
  - 完成时间
  - 右上角显示"已完成"印章水印
  - 不显示操作按钮

#### Scenario: 查看已取消订单详情
- **WHEN** 用户从订单列表进入已取消订单详情页
- **THEN** 系统显示运单卡片,包含:
  - 灰色渐变顶栏
  - 状态图标和"已取消"文字
  - 订单号
  - 核定提油量(吨)
  - 提油油库名称
  - 加油站名称
  - 车辆及司机信息(如果有)
  - 不显示操作按钮

#### Scenario: 取消订单
- **WHEN** 用户在待提油订单详情页点击"取消订单"按钮
- **THEN** 系统弹出确认对话框
- **WHEN** 用户确认取消
- **THEN** 调用取消订单API,成功后返回列表页并刷新

#### Scenario: 保存凭证
- **WHEN** 用户在待提油订单详情页点击"保存凭证"按钮
- **THEN** 系统生成运单凭证图片
- **AND** 显示保存/分享选项底部弹窗
- **WHEN** 用户选择保存到相册
- **THEN** 系统将图片保存到设备相册

#### Scenario: 代码结构要求(实现层面)
- **WHEN** 开发者查看订单详情页代码
- **THEN** 代码结构应遵循:
  - 主Screen文件行数不超过300行
  - UI组件按功能拆分到独立widget文件
  - 工具方法提取到utils目录
  - 每个组件职责单一明确
  - 符合项目的代码规范和架构要求
