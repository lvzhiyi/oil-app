# 接口联调与测试数据约定

适用于新增或修改接口、DTO、鉴权、上传、分页及依赖后端状态的页面。本文定义协作和验收方式，不代表已有 Mock 平台、账号或种子数据工具。

## 契约与记录位置

- 优先引用团队维护的 OpenAPI、接口平台或经前后端确认的接口说明，记录版本/更新时间；样例响应不能替代字段契约。
- 有 OpenSpec change 时，将接口链接、决定与联调状态写在对应 design/tasks 中；无 change 时写入关联 Issue。只维护一个权威记录，业务规则仍归对应 spec。
- Service、DTO 与后端约定冲突时先定位版本和影响，双方确认后更新；AI 不凭 Context7 或猜测补齐内部接口契约。

实施前按需确认：

| 项目 | 要确认的内容 |
| --- | --- |
| 请求 | 方法、路径、Header、鉴权、Path/Query/Body、Content-Type；上传字段及大小/类型限制 |
| 字段 | 类型、必填、可空、缺失与空值语义、默认值、枚举；未知枚举的处理 |
| 数值和时间 | 金额/数量的单位、精度与舍入责任，ID 类型，时间格式与时区；不得自行推断 |
| 返回 | HTTP 状态、业务 code、响应包裹层、成功/失败样例、错误码与用户提示 |
| 列表 | 页码起点、pageSize、排序、筛选编码、总数/hasMore、空页及重复数据处理 |
| 写操作 | 状态前置条件、权限、重复提交、幂等支持、超时后的结果确认；不要默认后端支持幂等 |
| 协作 | 前后端负责人、测试负责人或待指定、契约版本、可联调时间、测试环境、阻塞项 |

关键字段、权限或状态流转未确认时，暂停依赖实现；可先完成不依赖它的布局或工具调查。

## 本项目接入注意事项

- 沿用 Retrofit、DTO 与 netManager.clientDio，先阅读 lib/net/http_resp_interceptor.dart 和相关 Service。
- 当前响应拦截器会根据 extra 中的 noShowToast 影响传递给调用方的是完整响应还是 data。应核对实际返回类型，不重复解包或仅凭开关名称理解行为。
- 原始 HTTP 样例与拦截器处理后的 DTO 输入分开描述；解析测试应使用生产链路实际收到的结构。
- 鉴权异常、刷新和重试行为核对当前拦截器，不在新页面另建一套；避免拦截器与页面重复提示。
- 修改接口源定义后生成代码，审查生成差异，再验证解析和页面行为。

## Mock 与真实联调

| 阶段 | 能说明什么 | 不能替代什么 |
| --- | --- | --- |
| Fixture/Mock | 指定输入下的解析、状态与界面行为 | 真实鉴权、实际返回格式、服务端副作用 |
| 真实接口联调 | 指定环境、账号、数据和版本下端到端交互 | 未覆盖角色、边界、发布环境验证 |

1. 明确当前使用 Mock 或真实环境，在交付记录标注，禁止静默切换。
2. Mock 来自已确认契约，覆盖成功、空数据、业务失败、异常字段及相关边界；网络超时等可在测试层模拟。
3. Mock 仅放测试/明确的开发入口，不在生产路径“失败就返回成功假数据”，不携带到生产默认配置。
4. 后端就绪后使用同一场景完成真实联调，核对请求序列化、鉴权、响应处理及最终页面状态。
5. 发现差异先判定契约、Mock、客户端或后端哪方需调整；记录决定并更新相应测试，不用放宽 DTO 或吞异常掩盖问题。
6. 未联调时标记“实施完成，待联调”，这是“实施完成，待验证”的具体原因；不得标记该功能可合并，除非负责人明确接受分阶段交付并记录限制。

## 测试账号与数据

- 使用明确授权的测试环境和测试账号；真实联调前核对当前 base URL、环境配置及账号所属组织/站点，不能只凭 Debug 模式判断。
- 账号权限覆盖本次涉及的角色与数据隔离；仅正向账号通过，不能说明越权访问被阻止。
- 凭据通过团队批准的安全渠道提供，不写入 Markdown、fixture、日志、截图或 Git；文档只记录安全凭据引用位置和账号角色。
- 优先使用合成、可重建的数据；脱敏后也需核对是否仍包含个人、银行、司机或订单敏感信息。
- 为场景准备稳定初始条件、预期结果、创建/重置方式和清理负责人；缺少工具时手动操作并记录，不假定存在种子脚本。
- 测试数据使用可识别的测试标记和独立归属，避免并行人员修改同一订单或库存；不能依赖共享环境中偶然存在的固定 ID。
- 涉及支付、库存、取消、证件生成、上传或通知等副作用，先确认测试能力和可恢复方式；不得为验证触发真实支付、短信或生产数据写入。
- 清理仅限明确属于本次测试的数据，按已授权方式操作；无法安全清理时交接负责人，不批量删除共享数据。

## 最小场景清单

按功能挑选适用项，无需每次覆盖所有场景：

- 正常请求、空数据、字段缺失/null、约定的边界值和未知枚举。
- 无权限、登录过期、业务拒绝、服务错误、超时和重试。
- 分页首次/末页、筛选后刷新、重复点击、并发请求、退出页面后响应。
- 写操作成功后重新查询，确认服务端实际状态；超时先查结果，避免盲目重试造成重复写入。
- 涉及敏感状态流转时，覆盖禁止操作条件与跨组织数据隔离。

## 联调完成与交接

在对应 change/Issue 中保留以下记录，复用现有失败及中断交接机制：

```text
接口契约：链接、版本/确认时间
负责人：前端、后端、测试（未指定则明确写出）
运行环境：客户端提交/工作区状态、后端版本或部署时间（未知则说明）、环境别名
数据：账号角色、场景初始状态、测试数据标记、重建和清理方式（不含凭据）
结果：逐项标注 Mock 通过 / 真实联调通过 / 失败 / 未验证
证据：请求方式、脱敏的必要响应、关联 requestId/时间（适用时）、页面结果
差异与阻塞：责任人、待确认事项、恢复条件
清理：已清理 / 按约定保留 / 待负责人处理
```

接口联调问题按 [失败分类与交接](ai-workflow.md#验证失败和受阻交接)处理；跨会话按 [中断恢复](ai-workflow.md#中断与恢复交接)维护。验收必须明确实际覆盖范围，Mock 通过不升级为真实联调通过。
