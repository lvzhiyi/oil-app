# 项目说明
## 项目背景
在餐饮、本地生活等行业获客成本逐步上升的背景下，部分商户会有通过赠送给顾客彩票的营销手段，来达到吸引顾客消费、充值等目的。传统的赠送彩票都是商户自己去线下彩票店买好彩票，再赠送给进店客户，要做这件事情就依赖周边必须要有彩票门店，有诸多不便，于是互联网赠送彩票的方式就诞生。有开发能力的代理商也可通过申请开放平台api，做定制需求。

## 赠送彩票业务模式
赠送彩票是指有资质的平台，通过向国家平台购买彩票，然后转卖给第三方代理商（商家）。代理商购买彩票后，并不会立即生成彩票，只是买了一定数量的彩票生成权益，需要等到选择赠送给消费者时，消费者领取后，平台才会生成对应的一张彩票号码。

代理商购买彩票有两种方式：
- **套餐购买**：购买彩票权益套餐，套餐包含一定数量的彩票（权益），当代理商选择赠送给用户彩票时，需要先生成二维码，二维码可以批量生成静态二维码，也可以在赠送彩票页面生成动态二维码，用户扫码领取一张，则少一张。
- **余额充值**：充值一定的余额，赠送彩票时直接生成动态二维码，用户扫描领取一张，则扣一张彩票价格对应的余额。

## 名词说明
- **【用户】**：指C端实际领取彩票的用户
- **【代理商】**：指购买彩票权益，赠送给C端用户彩票的商户等
- **【平台】**：真正提供彩票生成的平台

## 项目定位
当前项目即代理商所使用的Flutter移动端应用，采用BLOC状态管理模式，支持Android和iOS双平台。

## 核心功能模块

### 1. 登录与权限管理
**角色类型**：老板、管理员、员工（登录不做区分，通过权限控制功能访问）

**权限划分**：
- **普通员工**：
  - 基本功能访问（仪表盘、赠送彩票、赠送记录查看）
  - 修改个人信息
  - **限制**：不可查看员工管理模块、不可充值、不可导出数据
  
- **管理员**：
  - 拥有普通员工所有权限
  - **额外权限**：可以禁用员工
  
- **老板**：
  - 拥有所有权限
  - **独有权限**：设置/禁用管理员、完整员工管理

### 2. 仪表盘功能
- **数据看板**：今日赠送张数、累计赠送张数、当前余额
- **报表**：最近七日赠送趋势图（折线图展示）

### 3. 购买彩票
**购买彩票**: 购买彩票权益套餐，套餐包含一定数量的彩票（权益），当代理商选择赠送给用户彩票时，需要先生成二维码，二维码可以批量生成静态二维码，不能使用充值的余额支付。
**套餐购买**：
- 100张 350元（3.5元/张）
- 500张 1600元（3.2元/张）  
- 1000张 3000元（3元/张）

### 4. 充值系统
**充值余额**：
- 最小充值金额100元
- 同一代理商不能同时发起多笔充值订单
- 充值落地页使用webview容器加载第三方支付平台H5页面
- 充值可填写备注
- 充值的余额只能作为动态二维码领取彩票时扣取使用。

**支付方式**：
- **支付宝/微信支付**：弹窗展示二维码图片，金额信息，扫码支付提示，完成支付后自动关闭弹窗（服务端已接入）
- **银行卡支付**：展示对公转账信息，支持上传转账凭证，平台审核处理
  - 公司名称：xxx科技有限公司
  - 开户银行：xxx银行  
  - 银行卡号：6225 88XX XXXX XXX

### 5. 赠送彩票
**生成方式**：
- **静态二维码**：批量生成赠送彩票领取的二维码链接（有效期7天）
- **动态二维码**：动态生成，每15秒自动刷新，用于实时赠送

**彩种支持**：
- 当前版本：仅支持双色球（前端写死）
- 后续迭代：将改为服务端返回枚举值，逐步支持3D/快乐8/七乐彩

**用户交互**：
- C端用户扫码后打开独立H5应用进行领取
- 二维码失效等交互逻辑由H5应用处理

### 6. 赠送记录管理
**列表展示字段**：
- 赠送日期
- 用户手机号
- 彩种（双色球/3D/快乐8/七乐彩）
- 号码
- 倍数  
- 状态（0：已失效，1：未中奖，2：已兑奖，3：待开奖，4：生成中，5：已中奖，6：兑奖中）
- 中奖金额（如已中奖）

**筛选功能**：时间范围/彩种/状态/手机号

**导出功能**：Excel导出（根据当前筛选条件，仅限老板和管理员）

**中奖处理**：代理商无需处理兑奖流程，没有奖金池，平台自动处理所有中奖兑奖业务，业务主流程只有购彩赠彩。

### 7. 员工管理（仅老板/管理员可访问）
**功能包含**：
- 员工列表：查看、删除、编辑
- 编辑员工：姓名、手机号、权限管理
- 员工状态：禁用员工、设置为管理员（仅老板）、禁用管理员（仅老板）

### 8. 个人中心
**基本信息**：

- 联系人姓名（可修改）
- 联系电话（可修改）
- 支持彩种展示

**功能设置**：

- **开放平台**（当前版本仅展示，后续迭代添加具体功能）：
  - API KEY
  - IP白名单
  - 每日调用次数上限

### 标准数据格式

#### 请求数据格式
所有API接口请求都采用标准JSON格式，与web开发完全一致：

- **Content-Type**: `application/json;charset=UTF-8`
- **请求体**: 标准JSON对象
- **数据类型**: 支持字符串、数字、布尔值、对象、数组等标准JSON数据类型
- **命名规范**: 使用下划线命名法（snake_case）

**请求示例**：
```json
{
  "phone": "13888888888",
  "password": "123456",
  "extra_info": {
    "device_type": "mobile",
    "app_version": "1.0.0"
  },
  "options": ["option1", "option2"]
}
```

#### 响应数据格式
所有API接口都遵循统一的响应格式：
```json
{
  "code": 0,           // 状态码，0表示成功
  "message": "success",  // 响应消息描述
  "data": {}             // 具体业务数据
}
```

**状态码说明：**
- `0`: 请求成功
- `401`: 登录失效，需要重新登录
- 其他数值: 请求失败，具体错误信息见message字段


### 认证相关接口

#### 1. 用户登录
- **接口路径**：`POST /auths/login`
- **请求参数**：
```json
{
  "phone": "手机号",
  "password": "密码"
}
```
- **响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "access_token": "用户的access_token",
    "refresh_token": "用户的refresh_token",
    "tenantUuid": "代理商UUID",
    "userName": "用户名",
    "phone": "手机号"
  }
}
```

#### 2. Token刷新
- **接口路径**：`POST /auths/refresh`
- **请求参数**：
```json
{
  "refresh_token": "用户的refresh_token"
}
```
- **响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "access_token": "new_access_token",
    "refresh_token": "new_refresh_token"
  }
}
```

#### 3. 退出登录
- **接口路径**：`POST /auths/logout`
- **响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": null
}

### 认证机制

**双Token无感刷新机制：**
1. **access_token**: 用于访问所有需要认证的接口
2. **refresh_token**: 用于刷新过期的access_token

**认证头信息：**
- Authorization: 登录成功后返回的access_token值，前面拼接Bearer + 空格，比如：Bearer xxdsadaedsad
- tenant-id: [代理商UUID] 登录成功获得，后续每个接口请求都必须携带
- Content-Type: application/json;charset=UTF-8

**无感刷新逻辑：**
- 基于HTTP响应状态码（401）检测token过期
- 系统自动拦截401响应，使用refresh_token刷新token
- 刷新成功后自动重试原始请求，用户无感知
- 刷新失败时引导用户重新登录
- 支持请求队列管理，防止并发刷新冲突

**Token轮换机制：**
- 每次刷新时服务器返回新的access_token和refresh_token
- 旧的refresh_token立即失效，提高安全性
- 支持token被盗用检测

### 登录页设计风格详解

登录页作为应用的入口页面，采用了现代化、极简主义、卡片式的设计风格，严格遵循了上述设计规范。

#### **视觉设计**
1. **背景设计**：使用了从上到下的渐变背景，颜色从 `#F8FAFF` 到 `#FFFFFF`，营造出清新、现代的视觉感受。
2. **Logo区域**：采用了带有圆角（20pt）和图标的容器作为Logo，图标使用了 `Icons.flash_on`，颜色为白色，背景色为主色调 `#4F7CF7`。品牌名称 "闪省" 使用了32pt的字体大小和700的字重，副标题 "智能省钱，触手可及" 使用了16pt的字体大小和400的字重，颜色为 `#8B8B8B`。
3. **登录表单**：采用了卡片式设计，背景色为白色，圆角为12pt，带有边框（`#E8E8E8`）和阴影效果（`BoxShadow(color: #4F7CF7.withValues(alpha: 0.05), blurRadius: 10, offset: Offset(0, 2))`）。表单标题 "欢迎登录" 使用了22pt的字体大小和600的字重，颜色为主色调 `#4F7CF7`。副标题 "请输入您的账号信息" 使用了14pt的字体大小，颜色为 `#8B8B8B`。

#### **组件设计**
1. **输入框**：遵循了设计规范中的输入框设计，包括背景色、边框、圆角（12pt）和内边距（水平16pt，垂直14pt）。手机号输入框和密码输入框都使用了自定义组件 `MobileNumberInput` 和 `PasswordInput`。
2. **按钮**：登录按钮使用了带有阴影效果的圆角按钮，背景色为主色调 `#4F7CF7`，圆角为12pt，阴影效果为 `BoxShadow(color: #4F7CF7.withValues(alpha: 0.2), blurRadius: 10, offset: Offset(0, 2))`。按钮文字 "立即登录" 使用了17pt的字体大小和600的字重，颜色为白色。在加载状态时，按钮内会显示一个白色的 `CircularProgressIndicator`。
3. **文本链接**：忘记密码链接使用了 `TextButton` 组件，文字 "忘记密码？" 使用了15pt的字体大小和500的字重，颜色为主色调 `#4F7CF7`。
4. **错误提示**：错误显示区域采用了扁平化设计，背景色为白色，圆角为12pt，带有红色边框（`#FF715C`）。区域内包含一个警告图标（`Icons.warning_amber_rounded`），错误信息文本使用了14pt的字体大小和500的字重，颜色为红色（`#FF715C`），以及一个关闭图标（`Icons.close`）。

#### **布局与交互**
1. **布局**：整体布局遵循了设计规范中的视觉层次，从上到下依次为Logo区域、登录表单、忘记密码链接、登录按钮和错误提示区域。各组件之间使用了标准间距（16pt, 24pt, 32pt, 48pt）进行分隔。
2. **交互**：登录按钮在加载状态下会变为不可点击状态，并显示进度指示器。错误提示区域可以通过点击关闭图标来清除错误信息。点击页面其他区域可以收起键盘。

这套设计确保了登录页的现代感、专业性和易用性，为用户提供了愉悦的登录体验。
